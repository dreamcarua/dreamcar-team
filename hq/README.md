# DreamCar HQ — Стіл SMM (Пілот)

**MVP-версія v0.1** — однофайлова SPA на ванільному JS, без бекенду.
Запущена на GitHub Pages як `dreamcarua.github.io/dreamcar-team/hq/`.

---

## Що це

Це робочий пілот першого «стола» в системі DreamCar HQ — інструменту для управління контент-планом SMM-команди. Технічне завдання живе поряд: [`../hq-smm.html`](../hq-smm.html) (рендер v1.1).

MVP реалізований у вигляді одного файлу `index.html` (HTML + JS + CSS), без зборки і без бекенду. Це дозволяє швидко показати UX команді, зібрати фідбек і прийняти рішення про повноцінну розробку.

## Що працює

| Модуль | Опис |

| **Дошка погоджень** | 3 колонки за роллю користувача, кнопки Погодити / Повернути з обов'язковим коментарем при поверненні |
| **Бібліотека** | Сітка плиток із мініатюрами-плейсхолдерами, фільтр по типу, пошук по тегах |

| **Глобальний пошук** | По тексту і хештегах |

## Що замоковано (на пілоті)

- **Зберігання** — localStorage браузера замість Supabase. Дані не синхронізуються між пристроями.
- **Авторизація** — демо-перемикач без OAuth.
- **Завантаження файлів** — кнопка показує hint, реального завантаження в Drive немає.
- **Telegram-сповіщення** — видно тільки в UI.
- **Soft-lock одночасного редагування** — без presence channel (потрібен бекенд).

## Як використовувати

1. Відкрий https://dreamcarua.github.io/dreamcar-team/hq/
2. При першому відкритті — автоматично сіються 25 публікацій, 12 креативів, 3 запуски, 5 користувачів.
3. У топбарі справа — кнопка з твоїм ім'ям → перемикач ролей. Спробуй різні ролі:
   - **Вадим (CEO)** — бачить дошку погоджень із картками на затвердження.
   - **Олександра (Тимлід)** — повний контроль над столом.
   - **Артем (Учасник)** — побачить свої публікації включно з повернутою на доопрацювання.
4. У консолі браузера (DevTools):
   - `HQ.reset()` — скинути дані і пересіяти.
   - `HQ.store` — інспектор стану.

## Шлях до production

Кроки описані в [`INTEGRATION.md`](INTEGRATION.md). У двох словах:

1. Створити Supabase проект → виконати [`db/schema.sql`](db/schema.sql), `db/rls.sql`, `db/seed.sql`.
2. Налаштувати Google OAuth у Supabase Auth.
3. Замінити `Store` layer у `index.html` на Supabase JS client (приклад в гайді).
4. Додати Google Drive API для реального завантаження креативів.
5. Розгорнути Telegram-бот для сповіщень.
6. Перенести з GitHub Pages на Vercel (краще для динамічного контенту).

Оцінка: 3-4 тижні розробки за умови, що Supabase і бот налаштовуються паралельно.
