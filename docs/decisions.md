## 03.09.2026 — памʼять агента ставиться в `docs/`, у гілку `memory-v8`
**Рішення:** система памʼяті v8 живе в `docs/` цього репо; коміт іде в гілку `memory-v8`, мерж — за Вадимом.
**Чому:** репо публічне і в нього кілька разів на день комітять боти (`survey: auto-update`, `cowork-notify-bot`, `auto cache bust`) — прямий push у `main` конфліктував би і не дав би власнику побачити diff. Каталог `docs/` тут не є коренем сайту (Pages роздає корінь `main`), тож памʼять не ламає публікацію — на відміну від `dreamcar-dashboard`, де `docs/` і є сайтом і памʼять довелося класти в `memory/`.
**На яких даних:** `gh api repos/dreamcarua/dreamcar-team/pages` → `source.branch=main`, `path=/`; `git log --oneline -300` — три боти-комітери.
**Наслідок:** доки гілка не злита, `report-to-telegram.yml` не тригериться (він слухає push у `main`).
**Статус:** активне

## 27.08.2026 — репозиторії DreamCar лишаються публічними
**Рішення:** відкотити приватизацію; повернути робочу частоту ETL (міграція 027 після аварійної 026).
**Чому:** для публічних репо GitHub Actions на standard runners безкоштовні й безлімітні. Приватизація перевела ~3700 хв/міс у платну квоту й за день зʼїла 90%, після чого довелося аварійно різати pg_cron-канал ETL.
**На яких даних:** розбір білінгу 24.08.2026 — квоту зʼїли інші, приватні проєкти (`abrisart-dashboards` 2004 хв + `sneco` 1154 хв), а не DreamCar.
**Наслідок:** усе, що комітиться сюди, публічне назавжди. Зміна видимості — рішення Вадима, з попереднім підрахунком хвилин.
**Статус:** активне

## 26.08.2026 — систему тех-звернень із Telegram знято з експлуатації
**Рішення:** повністю видалити перехоплення `#баг`/`#питання`/згадок у `tg-webhook`, cron-job `tech-requests-watchdog`, однойменну Edge Function, view і таблицю.
**Чому:** хибні спрацювання regex, `need_info` скидався на будь-який reply боту, і розбір черги вимагав відкритого Mac Вадима.
**На яких даних:** 16 рядків у `tech_requests`, усі `done` (архів — `onboarding/archive/tech_requests_dump_2026-08-26.json`). 🔬 частка хибних спрацювань не зафіксована.
**Наслідок:** звернення команди йдуть напряму Вадиму. Сторінка HQ «Нотатки» — окрема система, працює.
**Статус:** активне

## 24.08.2026 — часті легкі крони дорожчі за рідкі важкі; частоти зрізано
**Рішення:** `compress-creative` `*/3` → `*/10` з дешевою перевіркою черги перед `apt-get`; `tg-stats-mtproto` `*/30` → щогодини; `smm-content-watchdog` приведено до робочого вікна скрипта; `timeout-minutes` додано у 23 воркфлоу; `GITHUB_TOKEN` за замовчуванням → `read`.
**Чому:** GitHub округлює кожен job угору до хвилини. 86% ранів `compress` (257 із 298) не знаходили роботи, але встигали поставити ffmpeg — ~2 хв рахунку намарно.
**На яких даних:** таблиця топ-10 споживачів за місяць (`onboarding/CHANGELOG.md`, 24.08.2026).
**Наслідок:** свіжість статистики переглядів впала з 30 хв до години — свідомий розмін.
**Статус:** активне

## 14.08.2026 — SQL на проді застосовується воркфлоу, а не руками
**Рішення:** `apply-migration.yml` ганяє довільний `.sql` через Supabase Management API; fail-closed на будь-що крім 2xx; є `dry_run`.
**Чому:** до цього в репо не було жодного способу застосувати міграцію автоматично — файли лягали в `hq/db/migrations/` і чекали, поки хтось виконає їх руками.
**Наслідок:** міграція, застосована повз цей шлях, не лишає сліду в репо. Тому спершу файл, потім воркфлоу.
**Статус:** активне

## 28.07.2026 — автопост у Telegram перенесено з GitHub Actions в Edge + pg_cron
**Рішення:** вимкнути `schedule` у `tg-autopost.yml`, лишити його ручним бекапом; автопост іде `autopost-tg-enqueue` → `tg-post-send` (pg_cron кожні 2 хв).
**Чому:** scheduled cron у GitHub Actions давав до 80 хвилин затримки в пікові години; відео-пост на 22:00 вийшов о 22:44.
**Наслідок:** у процесу два канали запуску — Edge (головний) і ручний воркфлоу. Вимикати «зайвий» без звірки з `docs/architecture.md` → Trigger channels не можна.
**Статус:** активне

## 08.08.2026 — спалені секрети ротуються воркфлоу, літерали в коді замінено на env
**Рішення:** `rotate-hq-secrets.yml` заливає нові `HQ_CRON_SECRET` / `HQ_WEBHOOK_SECRET` у Edge env (чотири ключі, включно з legacy-аліасами `DC_CRON_SECRET` і `HQ_SECRET`); cron-джоби в базі оновлюються SQL-ом.
**Чому:** обидва секрети були захардкоджені у публічному репо (`cleanup-storage-orphans`, `detect-silent-uploads`, `tg-webhook`, міграція 019).
**Наслідок:** ротація тепер одна команда, а не обхід чотирьох місць. Значення у git не повертаються ніколи.
**Статус:** активне

## 11.08.2026 — банки ПУМБ і ОТП у Касі тільки через імпорт виписки
**Рішення:** не будувати авто-синк для ПУМБ/ОТП; лишити CSV/XLSX-імпорт.
**Чому:** моно і Приват мають прості токен-API. ПУМБ працює через Open Banking, і щоб тягнути дані автоматично, DreamCar має бути авторизованим НБУ TPP (регульований статус). ОТП дає лише корпоративний Click OTPay з ЕЦП.
**Наслідок:** надходження цих ФОП зʼявляються в Касі із затримкою на ручне завантаження; `kasa-stale-watchdog` не має вважати їх «застряглим синком».
**Статус:** активне
