04Механізм: прийняття = розгортання

Ланцюг «стратегія → черга → сесія → артефакт → статус → звіт» у v3.0 обірвався на першій ланці: план лежав у PDF, а виконувалось те, що заходило через живу розмову. v4.0 робить план таким, що запускає себе сам.

Вісім елементів самозапуску

1. Один файл черги (queue.md) як канон. 2. Правило першого кроку сесії (просунь топ або запиши skip). 3. Щоденний автозапуск 07:30 у proposal-mode (без прод-DDL/розсилок/Meta-мутацій без апруву). 4. WIP-ліміт 3. 5. Дайджест-блокери з лічильником днів прострочки. 6. Статус = артефакт (коміт з лінком, не слова). 7. Пʼятничний план/факт. 8. Тест на живучість: тиждень без живих сесій — черга все одно рухалась. Стратегія без залитої черги вважається неопублікованою.

Skip-log

Порожньо — заповнюють сесії. Кожен день, коли топ-задачу не вдалось просунути за ≤15 хв, лишає тут рядок із причиною. Порожній skip-log при статичній черзі — сам собою алерт.
