AUTOPOSTING · TG + Meta

Approved публікації автоматично йдуть у канали. TG — живий, event-driven. IG / FB / Threads — Phase 2, чекають Meta App credentials.

● TG LIVE · IG/FB/TH waits secrets

📐 Що це і навіщо

Колись постив руками: approve → копія тексту → завантажити креатив → опублікувати. 5-10 хв ручної роботи. Тепер: approve → автоматично через worker → потрібний час, канал, креатив. 0 хв ручки.

Чому event-driven

Класичний cron */5min — затримка до 5 хв. Event-driven через repository_dispatch — публікація через ~10-30 сек після approve.

Як працює

Approved → enqueue у tg_autopost_queue → GH Action worker через 30 сек → API call → Telegram

Defer logic

Якщо publish_at у майбутньому — worker НЕ постить зараз, чекає до часу. attempts не інкрементує.

🏗 Архітектура

publication.status='approved' │ ↓ enqueue_pending_autoposts() (per-platform) tg_autopost_queue + platform_autopost_status JSONB │ ↓ repository_dispatch OR cron */5min tg-autopost.yml → tg-autopost-worker.sh ├─ claim_autopost_jobs(1) — атомарний SKIP LOCKED ├─ Якщо publish_at у майбутньому → defer ├─ Якщо creative compress NOT ready → defer ├─ Post via TG Bot API ├─ complete_autopost_job() АБО fail_autopost_job() └─ Для Meta: meta-autopost-worker.sh → IG/FB/Threads

🔄 Flow станів

pending  →  processing  →  done
                  ↓
               failed (retry, max 3 attempts)

Кожна публікація має platform_autopost_status JSONB: {tg: 'done', ig: 'pending', fb: 'failed'}. mark_platform_autopost(pub_id, platform, status) атомарно мерджить.

🌐 Meta Phase 2 (IG + FB + Threads)

Код вже задеплоєний, чекає на 7 secrets у GH:

  • META_APP_ID, META_APP_SECRET
  • IG_USER_ID, IG_ACCESS_TOKEN (60d)
  • FB_PAGE_ID, FB_PAGE_ACCESS_TOKEN
  • THREADS_ACCESS_TOKEN

Інструкція: docs/META_AUTOPOST_SETUP.md

Що готово у коді

  • IG single image + carousel + Reels
  • FB Page single + carousel + video
  • Threads single + reply chain
  • Auto-retry logic, status JSONB merge

🎯 Use cases

SMM

Запланувати TG пост на майбутнє

  1. HQ → створи публікацію → publish_at = 2026-05-30 14:00 CEST
  2. Approvers погодили → enqueued
  3. Worker cron */5min бачить що ще НЕ час → defer
  4. О 14:00 — worker візьме і опублікує
