HQ — центр контенту

Усі публікації проходять тут: створення → погодження → планування → автопостинг. Multi-platform календар, multi-approver workflow, AI Copy, шаблони, real-time стани.

📐 Що це і навіщо

HQ — це єдине джерело правди про все що публікується від імені DreamCar. До HQ було: пости планувалися у Excel, копірайт писався у Google Docs, креативи кидалися у Telegram-чат, рев'ю — у Slack, фінал — ручний постинг.

HQ замінив 5 інструментів на одну сторінку. Усе в одному місці, з історією, ролями і автоматизацією.

Чому так

Multi-platform контент (TG/IG/FB/TikTok/YT) потребує різного часу публікації і різного формату, але одного джерела. Дерев'яні таблиці не масштабуються.

Як працює

SPA на ванільному JS + Supabase для даних і Realtime для синхронізації. Кожна дія тригерить наступну: rework → задача автоматично; approved → автопост у TG.

Ключове

Multi-approver AND-логіка — поки ВСІ approvers не погодили, статус не змінюється. Жоден один не може "обійти" процес.

🏗 Архітектура (як працює)

Frontend (HQ SPA) → Supabase │ │ │ Realtime subscribe │ PostgREST + RLS │ │ ↓ ↓ UI updates без F5 publications, approvers, creatives │ trigger │ ↓ team_tasks (auto-task on rework) ↓ notify-tg Edge Function ↓ Telegram DM/group

Стек:

  • Frontend: hq/index.html SPA, modular JS
  • Дані: Supabase Postgres (publications, creatives, approvers, history, comments)
  • Логіка: SQL RPC (register_approval, publication_to_task_on_rework trigger)
  • Доставка: Edge Functions notify-tg, cron-reminders, autopost-tg-enqueue

🔄 Workflow публікації

draft  →  review  →  approved  →  published
  ↑          ↓          ↓             ↓
  (creator) (approver) (system)    (TG auto)
            │
            └─ rework? → auto-task у Tasks → SMM править → review
  • draft — SMM пише, прикріплює креативи, ставить дату, обирає approvers. Авто-сейв.
  • review — натиснув «На погодження». Approvers отримують TG inline (✅ Погодити / ↩ Повернути).
  • rework — повернуто → SQL trigger створює задачу у Tasks автоматично.
  • approved — ВСІ approvers погодили (AND) → автопостинг enqueued.
  • published — після успішного посту у канал.

🎯 Use cases

SMM (Олександр)

Створити нову публікацію

  1. HQ → «+ Створити публікацію» (або клік у клітинці календаря)
  2. Заголовок, текст (AI Copy кнопка ⚡), платформи, час публікації
  3. Drag-drop креатив із Бібліотеки або завантажити
  4. Обрати approvers (Вадим + Артем)
  5. «На погодження» → approvers отримають TG inline
💡 Auto-save кожні 3 сек — нічого не загубиться.
Approver (Вадим, Артем)

Погодити публікацію (3 способи)

  1. TG inline: натискай ✅ під повідомленням @dreamcar_team_bot
  2. HQ UI: Дошка погоджень → колонка «На погодженні»
  3. /approve у боті: черга всіх постів що чекають голосу
💡 Multi-approver AND: статус стане «approved» тільки коли ВСІ погодили.
Approver

Повернути на доопрацювання

  1. ↩ у TG inline (двокроковий: причина → confirm)
  2. Або у HQ «Повернути» → структурована модалка (текст/креатив/дата/інше)
  3. Автоматично створюється задача у Tasks з due date = +1 день
💡 Якщо approved-пост змінили >10 символів — авто-revert у review.
SMM

AI Copy Assistant

  1. У картці — кнопка ⚡ «AI Copy»
  2. Опиши brief 1-2 реченнями
  3. Claude API повертає 3 варіанти у нашому brand voice
  4. Вибираєш + редагуєш
💡 Voice захардкожений — не сипле NASA / квитками / розіграшами.
CEO

Аналітика пайплайну

  1. HQ → Аналітика V3
  2. Funnel (draft → review → approved → published)
  3. Per-platform breakdown
  4. Rework cycles (індикатор якості SMM)
  5. Velocity — середній час від draft до published

⚙️ Ключові фічі

  • Календар: Місяць/Тиждень/День/Список + drag-drop + фільтр платформ
  • Картка публікації: char counter, per-platform preview, кольорові точки
  • Approvers: AND-логіка, @mention picker, chain прогрес у TG
  • Soft-lock: хто редагує — інші бачать
  • FTS пошук: tsvector full-text (Cmd+K глобал)
  • Шаблони: admin може редагувати/додавати
  • Bulk delete + Undo (5 сек)
  • ICS export: Google/Apple Calendar
  • SLA reminders: -10 хв + перевірка +10 хв
  • Theme + PWA + звуки
