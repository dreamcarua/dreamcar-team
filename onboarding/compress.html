COMPRESS QUEUE

Background стискання відео та фото для автопостингу. Цільова якість — максимальна, обмеження — 49.5MB через ліміти Telegram inline media.

📐 Що це і навіщо

Сирі відео з телефонів — 100-500MB. Telegram sendVideo (inline preview) має ліміт 50MB. Якщо більше — або не запоститься, або стане у sendDocument (без прев'юшки).

Compress Queue вирішує: SMM завантажує оригінал → система async стискає до ≤49.5MB → autopost іде з compressed_url.

Чому 49.5MB

TG ліміт = 50MB. Ставимо 49.5 щоб був buffer на metadata.

Як працює

2-pass H.264 high profile, preset veryslow, target 99% бюджету. Adaptive resolution. ImageMagick для фото — 2560×2560 q90.

Ключове

Не блокує UX. Approver побачить final якість. Worker працює у фоні через GH Actions cron */3min.

🏗 Архітектура

SMM uploads → R2 (signed URL via r2-sign-upload) │ creatives row: compressed_status='pending' │ ↓ GH cron */3min OR dispatch-workflow compress-creative.yml → worker.sh ├─ Download from R2 ├─ photo: ImageMagick → 2560x2560 q90 JPEG → R2 ├─ video: ffmpeg 2-pass H.264 → R2 ├─ complete_compress_job(url, size) └─ Trigger autopost dispatch

🔄 Flow станів

n/a (не потребує)  →  pending  →  processing  →  ready
                        ↓                ↓
                      failed         (worker err)
                        ↓
                   retry_compress(id) → pending

🎛 Tuning параметри

  • Target budget: 49.5MB (TG sendVideo ліміт)
  • Fill percent: 99% (target bitrate)
  • X264 preset: veryslow (max якість)
  • bframes: 12, ref: 8, subme: 10, aq-mode: 3
  • Audio: 96-128 kbps AAC
  • Resolution: 1920/1280/854/640px adaptive
  • HEIC: libheif + ImageMagick policy unlock
  • Photo: 2560×2560 q90 ≤9.5MB
  • Retry: overshoot → retry @ 93% bitrate
