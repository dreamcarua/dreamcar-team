### 💥 Workflows: міна сповільненої дії
- **`kill-all-ads.yml` мав annual cron `58 20 2 8 *`** — щороку 2 серпня о 20:58 вбивав би ВСІ Meta-кампанії. Cron видалений, лишився тільки ручний запуск.
- ETL sleep-loops (6×5хв mysql, 2×15хв fb-ads) — джоб тривав довше за інтервал тригера → шторм подвійних запусків і ~64 тис. idle-хвилин/міс. Тепер один прохід; каденс через cron `0,30` + pg_cron `:15,:45`. Помилки «canceled» зникли.

### 🔧 ETL data-loss баги
- `sync_sendpulse_deals.py`: курсор по `created_at` → старі угоди зі зміненим статусом ніколи не ресинкались. Тепер по `updated_at`.
- `sync_mysql_to_supabase.py`: запуск із `--limit` знищував курсор повного синку. Виправлено.
- `sync_fb_ads.py`: retry читав HTTP-код замість `error.code` з JSON (4/17/32 = Meta rate-limit); + `raise_for_status()` у пагінації (мовчазна втрата сторінок).

### 🔧 Retention: scheduler ламав dm_broadcast
- Старий scheduler підбирав `dm_broadcast`-розсилки (у них порожній `audience_list_id`) і позначав їх **failed**. Тепер фільтр `.or('send_mode.is.null,send_mode.neq.dm_broadcast')` — їх обробляє тільки `retention-bot-broadcast`.
- - фікс escapeHtml-мапи в тій самій функції (v43).

### 🔧 Tasks-фронт: витоки
- `onAuthStateChange(TOKEN_REFRESHED)` дублював realtime-канали кожну годину → тепер повний ребут тільки на SIGNED_OUT / перший вхід.
- Drag-drop хендлери накопичувались на персистентних колонках → N дублікатів UPDATE за один дроп. Bind-once guard.
