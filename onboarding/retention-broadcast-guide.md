# Нативна DM-розсилка в бота DreamCar.ua — повна інструкція

> Ретеншн-розсилка напряму підписникам Telegram-бота **DreamCar.ua** (не в канал/групу, а в особисті повідомлення).
> Створено на запит Віри, 29–30.07.2026.

---

## 1. Що це і навіщо

Раніше канал `tg` у ретеншні вмів слати лише **один текстовий** `sendMessage` в один чат і ігнорував медіа, кнопки та аудиторію. Тепер це повноцінна **сегментована DM-розсилка**: текст із форматуванням, фото, відео, відеозамітка (кружечок), медіагрупа, inline-кнопки — доставляється кожному підписнику бота в особисті.

Ключовий принцип безпеки: **лише DM** — розсилка ніколи не йде в групи/канали (Віра наголошувала).

---

## 2. Як це працює (архітектура)

```
Композер (/retention)  →  retention_messages (draft→review→approved→scheduled)
        │                          │
        │ (медіа, кнопки,          │ (погодження в TG)
        │  відеозамітка, DM-only)  ▼
        │                   retention-bot-broadcast (Edge-воркер)
        │                          │  бере аудиторію з bot_subscribers
        ▼                          ▼  шле через бота DreamCar.ua (PUBLIC_BOT_TOKEN)
   creative_*                 14 043 підписники → особисті повідомлення
```

**Компоненти:**
- `retention_messages` — картка розсилки: `title`, `body`/`preview_text`, `publish_at`, `tg_buttons`, `video_note_creative_id`, `dm_only`, `send_mode`, `audience_filter`.
- `bot_subscribers` — база підписників бота (chat_id, username, ім'я, мова, `raw` зі SendPulse-змінними). Зараз **14 043** активних.
- `sendpulse-subscribers-sync` — Edge-функція, що тягне підписників зі SendPulse (READ-ONLY) → `bot_subscribers`. Щодня о 03:30 (pg_cron `sendpulse-subscribers-sync-daily`).
- `retention-bot-broadcast` — Edge-воркер, що робить власне розсилку.

---

## 3. Як користуватись (Віра / SMM)

1. Відкрий **team.dreamcar.ua/retention** → **+ Нова розсилка**.
2. Канал — **Telegram**. З'явиться блок **📨 TG-ОПЦІЇ**.
3. Заповни:
   - **Заголовок** і **Тіло** (підтримує HTML-форматування, підказка у блоці TG-опцій).
   - **Дата і час** відправки.
   - **Креативи** (📸 з бібліотеки) — 1 фото/відео = одиночний пост; кілька = медіагрупа (альбом).
   - **🎥 Відеозамітка** — обери відео з прикріплених, щоб пішло кружечком перед постом.
   - **🔘 Кнопки** — «+ Кнопка», впиши текст + URL (скільки треба).
   - **🔒 Лише DM-підписникам** — увімкнено за замовчуванням (групи/канали виключені).
   - **Аудиторія** — фільтри (див. розділ 5) + кнопка «↻ Оцінити» показує к-сть підписників.
4. **Зберегти** → **На погодження** (обери погоджувача). Далі — стандартний воркфлоу approve.
5. Після `approved`/`scheduled` у призначений час воркер розсилає автоматично.

## 4. Що вміє повідомлення

| Елемент | Як | Примітка |
|---|---|---|
| Форматування | HTML у тілі: `<b> <i> <u> <s> <code> <a>` | Підказка в блоці TG-опцій |
| Фото / відео | Креатив із бібліотеки | Стиснуте серверним воркером |
| Відеозамітка (кружечок) | Поле «Відеозамітка» | Окреме кругле відео, без підпису/кнопок |
| Медіагрупа (альбом) | 2+ креативи | Кнопки йдуть окремим повідомленням під альбомом |
| Inline-кнопки | Конструктор кнопок | Текст + URL |

Технічно: великі відео (>20МБ) — multipart; для швидкості на 14k медіа завантажується **1 раз** і далі reuse `file_id`; ліміт ~22 msg/с (у межах TG). Хто заблокував бота (403) — автоматично позначається неактивним.

## 5. Аудиторія і сегментація

**База:** `bot_subscribers` — 14 043 активних підписники бота DreamCar.ua. Оновлюється щодня зі SendPulse. «30–40 тис.» — це загальна база учасників; активних DM-підписників бота саме ~14k.

**Що є для сегментації (реальні SendPulse-змінні у кожного підписника):**

| Змінна | Покриття | Для сегменту |
|---|---|---|
| `Phone` / `phone` | ~8200 | є контакт |
| `кількість замовлень` (+ etron / bmw / iphone) | 2600–3700 | активність / LTV |
| `bmwx6`, `мустанг`, `Next18` | 1800–3000 | інтерес до конкретного авто/призу |
| `gender`, `age`, `location` | ~1360 | демографія |
| `status` | ~1340 | статус учасника |
| `color`, `trust`, `trig` | ~1350 | анкетні дані |

Приклади сегментів, які можна зібрати: «замовляли BMW ≥1», «інтерес до e-tron», «жінки 25–40 з Києва», «є телефон, але 0 замовлень» (дожим).

**Як реалізовано зараз:** розсилка йде на **всю активну базу** (dm_broadcast). Дані для сегментів уже лежать у `bot_subscribers.raw → contact.variables`.

**Phase 2 (наступний крок):** фільтр по SendPulse-змінних у композері — вибір змінної + оператор (=, ≥, містить) → воркер будує вибірку по `raw`. Плюс альтернатива: підтягувати конкретний **SendPulse-список/сегмент** за його ID (поле «ID списку/чату» вже є в композері). Це зробимо після твоєї відмашки на прод.

---

## 6. Безпека (важливо)

- **DM-only:** dm_broadcast завжди шле лише в особисті. Групи/канали фізично виключені.
- **🔒 Kill-switch:** розсилка на **аудиторію бота заблокована** на рівні коду до відмашки Вадима. Навіть із валідним секретом реальна відправка на `bot_subscribers` повертає `403 blocked`. Тест дозволено **лише на команді** (`source=team`).
- **Увімкнення прод:** коли Вадим дає добро — виставити `PROD_BROADCAST_ENABLED=1` у Edge env (одна дія). Токен публічного бота (`PUBLIC_BOT_TOKEN`) уже в env, `getMe` підтверджено.
- Реальна відправка вимагає `?confirm=1` + секрет; без них — dry-run (лише показує план і к-сть).

---

## 7. Прод-запуск (коли буде відмашка)

1. Вадим: `PROD_BROADCAST_ENABLED=1` у Edge env (через workflow або одну команду — попрошу окремо).
2. Розсилка на всю базу або сегмент — через композер (approve → час) або ручний виклик воркера з `?confirm=1`.
3. Моніторинг: `retention_messages.sent_count` / `failed_count`, авто-відписка заблокованих.

---

## 8. Технічні деталі

- Edge: `retention-bot-broadcast` (розсилка), `sendpulse-subscribers-sync` (аудиторія).
- Cron: `sendpulse-subscribers-sync-daily` (jobid 5986, 03:30 UTC).
- Таблиці: `bot_subscribers`, `retention_messages` (+ поля `tg_buttons`/`video_note_creative_id`/`dm_only`/`send_mode`).
- Токени: `PUBLIC_BOT_TOKEN` (бот DreamCar.ua) → fallback `TG_BOT_TOKEN` (командний, для тесту).
- 🔑 Гоча: у SendPulse справжній TG chat_id = `contact.telegram_id` (не `contact.id` — то внутрішній SP-id).
