Verify Publication — T+3 хв підтвердження

Автоматична перевірка через 3 хв після publish_at з manual confirmation у TG. Заміна Instagram Graph API (не вийшло без Business акаунту).

Концепція

Через 3 хвилини після запланованого publish_at публікації бот шле повідомлення у group chat і кожному stakeholder (approvers + responsibles + author) з кнопками:

  • ✅ Опубліковано — status='published', notify ВСІМ "✓ Підтверджено"
  • ❌ Не вийшло — алярм у group + DM усім
  • ↻ Переніс +1 год — publish_at +60min, цикл повторюється
  • 🔗 Відкрити в SMM — лінк на pub у вебі

Чому manual (не IG API)?

🟡 Try-and-fail Instagram Graph API

Спочатку планували авто-перевірку через IG Graph API: бот заходить у @dreamcar.ua, шукає новий пост у вікні publish_at ± 30 хв. Не вийшло бо:

  • IG @dreamcar.ua — Creator акаунт, не Business
  • Meta Graph API instagram_business_account повертає null для Creator
  • Переключити на Business → втрата Creator-only фіч (Spotlight music)
  • Make.com Instagram trigger — потребує сторонній Anysite ($) або RSSHub (нестабільно)

Manual confirmation у TG — 1 клік від команди, 0 залежностей, працює для будь-якої платформи.

Як це працює крок-за-кроком

Step 1 · INSERT/UPDATE
Pub з'являється/оновлюється з status approved/review/in_work/rework

Тригер trg_pub_verify_schedule AFTER INSERT/UPDATE OF status/publish_at автоматично викликає функцію schedule_publication_verify(pub_id, publish_at).

Step 2 · One-shot cron створено
У cron.job з'являється запис verify_pub_<uuid>

Cron expression точно на publish_at + 3 хвилин у UTC. Наприклад для publish_at = 2026-06-10 09:00 UTC → cron 3 9 10 6 *.

Step 3 · Cron спрацьовує T+3 хв
HTTP POST → edge fn verify-publication-ig

Edge fn перевіряє чи pub ще не verified. Якщо ні — шле message у TG group + DM кожному stakeholder з 4 кнопками.

Step 4 · Команда натискає
Callback handler у tg-webhook обробляє рішення
  • vrfy:confirm:<id> → status=published + notify-tg fanout ✅
  • vrfy:miss:<id> → verified_status=missed + алярм
  • vrfy:resched:<id>:60 → publish_at += 60min, нова one-shot cron job
Step 5 · Auto-cleanup
Cron job видаляється з cron.job

Edge fn у кінці викликає cron.unschedule(verify_pub_<id>) щоб job не повторювався наступного року на тій же даті.

Tригери у БД

trg_pub_verify_schedule
  AFTER INSERT OR UPDATE OF status, publish_at, deleted_at, verified_at
  ON public.publications
  FOR EACH ROW EXECUTE FUNCTION trg_publications_schedule_verify();

trg_pub_verify_unschedule
  AFTER DELETE ON public.publications
  FOR EACH ROW EXECUTE FUNCTION trg_publications_unschedule_verify();

trg_pub_platforms_reschedule
  AFTER INSERT OR DELETE ON public.publication_platforms
  FOR EACH ROW EXECUTE FUNCTION trg_pub_platforms_reschedule_verify();

Колонки у publications

  • verified_at (timestamptz) — коли була підтверджена/відхилена
  • verified_status (text) — 'ok', 'missed', 'requested', 'error', 'skipped', 'ok_legacy'
  • verified_evidence_url (text) — лінк на пост (IG permalink, якщо є)
  • verify_retry_count (int) — скільки разів retried

Що НЕ створює задачу

Fix 07.06.2026: якщо pub переходить у approved і її publish_at < NOW() - 1 година — задача "Опублікувати" НЕ створюється (бо публ. фактично вже опублікована, або давно прострочена).

Раніше це створювало fake задачі на CEO у Tasks → false-positive notifications.

Idempotency

  • Якщо pub вже має verified_at IS NOT NULL — edge fn skip'ить
  • Якщо pub вже status='published' — edge fn skip'ить
  • Кнопка ✅ Опубліковано перевіряє pubBefore.status === 'published' перед UPDATE

Edge cases

Cron спрацював ДО того як хтось натиснув

Якщо T+3 хв минуло, але pub ще не published у БД (наприклад, забули у соцмережі) — алярм автоматично йде у group.

Pub видалена між schedule і fire

Тригер DELETE викликає safe_unschedule → cron job видаляється. Якщо вже спрацював — edge fn skip'ить бо pub not found.

Publish_at перенесено вручну (UI)

Тригер UPDATE OF publish_at → schedule_publication_verify викликається знов:

  • Старий cron job видаляється (safe_unschedule)
  • Новий cron job створюється на новий час

Pub без platforms

Тригер `trg_publications_check_platforms` БЛОКУЄ transition у review/approved/published без жодного platform. RAISE EXCEPTION → UI помилка.

Troubleshooting

T+3 хв пройшло, нічого не прилетіло

  1. Перевір cron.job WHERE jobname = 'verify_pub_<uuid_no_dashes>' — чи створений?
  2. Перевір net._http_response навколо T+3 хв — успішний?
  3. Перевір edge fn logs verify-publication-ig
  4. Можливо pub без platforms (треба додати хоча б одну)

Кнопки в TG не реагують

  1. Перевір що користувач має users.tg_chat_id
  2. Перевір що edge fn tg-webhook ACTIVE (latest version)
  3. Можливо callback_data >64 байт — Telegram ріже
