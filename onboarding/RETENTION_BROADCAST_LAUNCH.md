# 🚀 Ретеншн-бродкаст на базу — чек-лист прод-запуску

> Оновлено 10.08.2026. Нативна DM-розсилка в бота учасників (не SendPulse-розсилка).

## Стан на 10.08.2026
- **База:** 14 516 контактів синхронізовано з SendPulse (READ-ONLY). Активних для розсилки — **13 378** (1 138 відписаних тепер коректно виключені: `is_active=false`).
- **Сегментація:**
  - `user_status` ✅ працює: `loyal` (1 239 — «давно з вами»), `new` (107), `cold` (15). Решта без survey-змінної `trust` → без сегмента (шлються як «вся база»).
  - `tariff` ⛔ **порожній** — SendPulse не зберігає пакет. Щоб сегментувати по тарифу (1/5/15/50), треба зіставити з `dashboard_deals` по phone/email → окрема задача (H2).
- **Воркер** `retention-bot-broadcast`: DM-only, rate-limit, авто-деактивація при blocked/kicked, фільтри `is_active + user_status (+tariff коли зʼявиться)`.

## 🔴 Що потрібно від Вадима (2 дії, одна команда)
1. **Токен публічного бота** (де 30-40к підписників) — щоб воркер слав від імені бота учасників:
   ```
   printf '%s' '<PUBLIC_BOT_TOKEN>' | gh secret set PUBLIC_BOT_TOKEN --repo dreamcarua/dreamcar-team \
     && gh workflow run sync-public-bot-token.yml --repo dreamcarua/dreamcar-team
   ```
2. **Відмашка на прод.** До неї — тест лише на команді (`?source=team`), НЕ на аудиторії. Прод-розсилка на 13k = ескалація, підтверджуєш явно.

## Чек-лист перед першою прод-розсилкою
1. `sync-public-bot-token.yml` пройшов, `getMe` показав правильного бота.
2. Тест на команді: створити розсилку у столі Ретеншн → `send_mode=dm_broadcast`, `?source=team` → перевірити, що прийшло тобі/команді (текст+медіа одним повідомленням, кнопки, форматування).
3. Перевірити сегмент і **очікувану кількість** у прев'ю розсилки (має показувати ≤13 378, з фільтром — менше).
4. Kill-switch: прод-відправка вимагає `PROD_BROADCAST_ENABLED=1` (Edge env) — вмикати тільки на час розсилки.
5. Запуск невеликим сегментом спершу (напр. `user_status=loyal` 1 239) → перевірити доставку/помилки → далі решта.

## Далі (H2, роблю без відмашки на самі розсилки)
- Зіставлення `tariff` з `dashboard_deals` (phone/email) → сегментація по пакету.
- Дозаповнення `user_status` для решти бази (survey-змінна `trust` є лише в ~9%): або з deals (перша/повторна покупка), або лишити «без сегмента».
- Сегмент «сплячі» (немає покупок N днів) для реактиваційних серій.
